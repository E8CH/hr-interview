# 면접 진행 도우미 — 사용자 가이드

지원자 명단을 받아서 면접 시간표를 만들기까지, 순서대로 무엇을 하면 되는지 정리한 문서다.

이 시스템은 **인사 담당자**와 **현업 부서(면접관)** 두 사람이 번갈아 가며 쓴다.
한쪽이 끝내야 다른 쪽이 할 일이 생기므로, 순서를 건너뛰면 다음 화면이 비어 있다.

---

## 전체 흐름 한 장

```
인사 ①  지원자 명단 받기
인사 ②  팀별 명단 나누기
        ↓
부서 ①  우리 팀 면접 담당자 정하기
        ↓
인사 ③  부서에 명단 보내기
        ↓
부서 ②  면접자 담당자 매칭
        ↓
인사 ④  면접 시간표 만들기
```

왼쪽 사이드바에도 같은 순서가 적혀 있다. 지금 누구 차례인지 헷갈리면 거기를 보면 된다.

---

# 0단계 · 최초 1회만 하는 준비

처음 이 PC에서 실행하는 경우에만 필요하다. 두 번째부터는 건너뛴다.

PowerShell을 열고:

```powershell
cd C:\Users\HEMICOLON\Documents\WORK\VIBE\hack\hr-interview-system
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

`Set-ExecutionPolicy`는 스크립트 실행을 허용하는 설정이다. 물어보면 `Y`를 누른다.

가상환경 두 개(`.venv`, `.venv-ui`)는 이미 만들어져 있으므로 따로 설치할 것은 없다.

---

# 1단계 · 시스템 켜기

프로젝트 폴더에서 아래 중 **하나만** 실행한다.

```powershell
.\start_all.ps1
```

| 상황 | 쓸 스크립트 |
|---|---|
| 코드를 고쳐 가며 작업할 때 | `.\start_all.ps1` — 파일을 저장하면 자동 재기동된다 |
| 그냥 빨리 켜고 싶을 때 | `.\start_all_fast.ps1` |
| 시연 직전, 가장 빠르게 | `.\start_all_ultra.ps1` |

검은 창이 9개 뜬다(서비스 7개 + 화면 1개 + `Watchdog` 창 1개).
**이 창들은 끄지 말고 그대로 둔다.**

`Watchdog` 창은 10초마다 서비스가 살아 있는지 확인하다가, 죽은 것이 있으면
**그 서비스만** 다시 띄운다. 되살릴 때 이런 줄이 찍힌다.

```
[14:22:10] 04-scheduler (:8004) 응답 없음 - 재시작 #1
```

죽은 창은 `Press Enter to close` 상태로 남겨 둔다. 왜 죽었는지 봐야 하기 때문이다.
새로 뜬 창은 제목 줄에 `[watchdog 재시작]`이 붙는다.

기동이 끝나면 `All services OK` 또는 `All 7 ports OPEN`이 보인다.
브라우저가 자동으로 열리지 않으면 직접 주소창에 입력한다:

**http://localhost:8501**

## 잘 켜졌는지 확인

화면 왼쪽 위에서 역할을 **시스템 관리자**로 바꾸면 서비스 7개 상태가 카드로 나온다.
전부 초록불이면 준비 완료다.

터미널에서 확인하고 싶으면:

```powershell
.\.venv\Scripts\python.exe tools\test_runner.py health
```

# 2단계 · 회차 정하기

화면 왼쪽 사이드바에 **회차 번호**를 입력하는 칸이 있다. `R20260731-01` 같은 형태로 자동으로 채워져 있다.

> **이 값은 처음에 한 번 정하고 끝까지 바꾸지 않는다.**
> 중간에 바꾸면 앞에서 만든 명단·배정·시간표를 시스템이 찾지 못한다.

역할 선택도 같은 사이드바에 있다. 아래 진행에 따라 **인사 담당자** ↔ **현업 부서(면접관)** 를 오간다.

---

# 3단계 · 인사 담당자 ① — 지원자 명단 받기

역할을 **인사 담당자**로, 메뉴를 **지원자 명단 받기**로 놓는다.

| 순번 | 할 일 |
|---|---|
| ① 엑셀 파일 올리기 | 각 팀에서 받은 지원자 엑셀을 올린다. 여러 개를 한꺼번에 올려도 된다 |
| ② 맞춰 볼 파일 고르기 | 올린 파일 중 서로 대조할 것을 고른다 |
| ③ 맞춰 본 결과 | 파일 사이에 어긋난 부분을 보여 준다. 빠진 사람·중복된 사람을 여기서 잡는다 |
| ④ 확정 명단 만들기 | 대조가 끝나면 이번 회차의 최종 지원자 명단을 확정한다 |

**④까지 눌러야 다음 단계로 넘어간다.** ③에서 멈추면 2단계 화면에 명단이 안 나온다.

---

# 4단계 · 인사 담당자 ② — 팀별 명단 나누기

메뉴를 **팀별 명단 나누기**로 옮긴다.

| 순번 | 할 일 |
|---|---|
| ① 팀 배정하기 | 확정된 지원자를 팀별로 자동 배분한다 |
| ② 팀별 면접 순서 잡기 | 팀 안에서 면접 볼 순서를 정한다 |
| ③ 나눈 결과 확인 | 팀별로 몇 명씩 갔는지, 왜 그 팀에 갔는지 사유를 확인한다 |
| ④ 손보고 확정하기 | 직접 옮기고 싶은 사람을 조정한 뒤 확정한다 |

여기서도 **④ 확정까지 마쳐야** 부서 쪽 화면에 명단이 나타난다.

---

# 5단계 · 현업 부서 ① — 우리 팀 면접 담당자 정하기

사이드바에서 역할을 **현업 부서 (면접관)** 로 바꾼다. 메뉴는 **우리 팀 면접 담당자 정하기**.

| 순번 | 할 일 |
|---|---|
| ① 담당자 명단 준비하기 | 두 가지 방법 중 하나를 쓴다 |
| ② 이번 회차에 들어갈 담당자 | 등록된 사람 중 이번에 실제로 면접에 들어갈 사람만 체크한다 |

①의 두 가지 방법:

- **팀마다 자동으로 만들기** — 시연·테스트용. 버튼 한 번으로 담당자 명단이 생성된다
- **엑셀로 올리기** — 실제 담당자 명단 엑셀을 올린다

②에서 고른 사람에게만 뒤에서 시간 조사 메일이 나간다. **여기를 비워 두면 6단계에서 보낼 대상이 없다.**

---

# 6단계 · 인사 담당자 ③ — 부서에 명단 보내기

역할을 다시 **인사 담당자**로 되돌리고, 메뉴는 **부서에 명단 보내기**.

| 순번 | 할 일 |
|---|---|
| ① 이번에 연락할 담당자 | 5단계에서 부서가 골라 둔 담당자가 여기에 뜬다 |
| ② 각 팀에 명단 보내기 | 팀별 면접자 명단을 각 부서로 발송한다 |
| ③ 가능한 시간 물어보기 | 담당자들에게 가능한 시간을 묻는 요청을 보낸다 |
| ④ 누가 답했는지 보기 | 회신 현황을 본다. 안 온 사람은 여기서 확인해 독촉한다 |
| ⑤ 모인 가능 시간 | 모인 시간대를 한눈에 본다 |

**⑤에 시간이 충분히 모이기 전에 8단계(시간표 만들기)로 가면 배치가 실패하거나 빈 시간표가 나온다.**
회신이 어느 정도 찼는지 ④에서 확인하고 넘어간다.

---

# 7단계 · 현업 부서 ② — 면접자 담당자 매칭

역할을 **현업 부서 (면접관)** 로, 메뉴를 **면접자 담당자 매칭**으로 바꾼다.

화면 맨 윗줄에 인사팀에서 온 요청과 할 일이 먼저 표시된다.

| 순번 | 할 일 |
|---|---|
| ① 면접에 들어갈 수 있는 우리 팀 담당자 | 시간 회신을 마친 담당자 목록 |
| ② 면접 볼 사람 고르고, 담당자 정하기 | 받은 명단에서 실제로 면접할 지원자를 고르고 담당자를 짝지어 준다 |
| ③ 우리 팀 면접 시간표 | 우리 팀 기준으로 짜인 시간표를 확인한다 |
| ④ 담당자별 면접 일정 | 담당자 한 사람씩 일정이 어떻게 잡혔는지 본다 |
| ⑤ 인사 담당자에게 보내기 | 확인이 끝나면 인사팀으로 회신한다 |

**⑤를 눌러야 인사팀 쪽에서 최종 시간표를 만들 수 있다.**

---

# 8단계 · 인사 담당자 ④ — 면접 시간표 만들기

역할을 **인사 담당자**로, 메뉴를 **면접 시간표 만들기**로 옮긴다.

| 순번 | 할 일 |
|---|---|
| ① 시간표 만들기 | 모인 시간과 매칭 결과로 전체 시간표를 자동 생성한다 |
| ② 면접 못 보는 사람 | 아직 짝이 안 지어진 사람을 보여 준다. 남았으면 앞 단계로 돌아가 보완한다 |
| ③ 만들어진 시간표 보기 | 완성된 전체 시간표를 확인한다 |

②가 비어 있으면 전원 배치가 끝난 것이다.

---

# 9단계 · 시스템 끄기

작업이 끝나면 프로젝트 폴더에서:

```powershell
.\stop_all.ps1
```

검은 창을 하나씩 닫을 필요 없이 한 번에 정리된다.
감시(`Watchdog`)를 **먼저** 끄고 서비스를 내리므로, 내린 서비스가 다시 살아나지 않는다.

> 창을 손으로 하나씩 닫으면 감시가 남아서 계속 되살린다.
> 끌 때는 반드시 `.\stop_all.ps1`을 쓴다.

---

# 자주 막히는 곳

**다음 화면이 텅 비어 있다**
→ 앞 단계의 마지막 순번(보통 ④ 또는 ⑤ "확정"·"보내기")을 안 눌렀을 가능성이 가장 크다. 되돌아가 확인한다.

**회차 번호가 중간에 바뀐 것 같다**
→ 사이드바의 회차 번호를 처음 값으로 되돌린다. 데이터는 회차 번호로 묶여 있다.

**서비스가 빨간불이다**
→ 해당 포트의 검은 창을 찾아 오류 메시지를 본다. 창 제목에 포트 번호가 적혀 있다(`Version-Manager :8001`).
   간단히는 `.\stop_all.ps1` 후 다시 `.\start_all.ps1`.

**화면(8501)이 아예 안 열린다**
→ Streamlit은 `.venv`가 아니라 `.venv-ui`에 설치돼 있다. 수동 실행은 이 명령이다:
```powershell
.\.venv-ui\Scripts\python.exe -m streamlit run tools\test_console.py
```

**한글이 깨져 보인다**
```powershell
chcp 65001
```

# 부록 · 화면 없이 터미널로 확인하기

발표 전 점검이나 문제 추적에 쓴다.

```powershell
# 서비스 7개 상태
.\.venv\Scripts\python.exe tools\test_runner.py health

# 전체 흐름 자동 실행(샘플 데이터)
.\.venv\Scripts\python.exe tools\test_runner.py scenario happy

# 각 DB에 데이터가 쌓였는지
.\.venv\Scripts\python.exe tools\test_runner.py db

# 특정 회차가 어디서 막혔는지 이벤트로 추적
.\.venv\Scripts\python.exe tools\test_runner.py events R20260731-01

# 위 세 개(health → happy → db)를 한 번에
.\test_all.ps1
```

각 서비스의 API 문서는 `http://localhost:8001/docs` ~ `http://localhost:8007/docs`.
