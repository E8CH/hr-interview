# HR 후보자 팀 배포 업무프로세스 명세서

> **문서 목적**  
> 지금까지 HR 담당자 개인의 판단(암묵지)으로 이루어지던 “취합파일 → 팀별 희망지원자 파일” 배포 과정을,  
> AI Agent가 동일한 결과를 재현하고 담당자가 검수할 수 있도록 **명시적 프로세스**로 규정한다.

- 문서 버전: v1.0
- 최종 갱신일: 2026-07-29
- 관련 파일: `취합파일.xlsx`, `희망지원자_{팀명}.xlsx` (5개 팀)
- 대상 시스템: HR 면접일정 자동생성 AI Agent (전(前)단계 배포 모듈)

---

## 0. 용어 정의

| 용어 | 정의 |
|---|---|
| **취합파일(Master)** | 서류 심사가 끝난 지원자 원장. 이번 회차 기준 467명(전원 결과P). |
| **팀 배포본** | 취합파일에서 특정 팀 검토용으로 발췌한 서브 파일. 파일명 형식 `희망지원자_{팀명}.xlsx`. |
| **분배 사유 태그** | 특정 지원자가 특정 팀에 배포된 근거. 최소 1개 이상 필수. |
| **팀 프로필** | 각 팀의 주력 직무·선호 전공군·학위 비율 목표 등을 정의한 팀 정체성 파라미터 집합. |
| **암묵지(Tacit)** | 파일이나 문서에 남지 않고 담당자 경험에만 존재하는 판단 규칙. |
| **명시지(Explicit)** | 규칙집·컬럼·수치로 재현 가능한 판단 규칙. |

## 1. 프로세스 총괄 개요

```
┌────────────────────────────────────────────────────────────┐
│  STEP 1. 서류합격자 필터                                     │
│  STEP 2. R&D 직군 필터                                       │
│  STEP 3. 조직 필터 (제1기술원 우선 + 제2사업부 소량 포함)      │
│  STEP 4. 팀별 주력 직무 매칭                                  │
│  STEP 5. 팀별 전공 매칭                                       │
│  STEP 6. 학사/대학원 비율 조절                                │
│  STEP 7. 특수 태그(타겟랩·지도교수) 우선 배정                  │
│  STEP 8. 복수 검토 대상 중복 배포 + 사유 기록                  │
│  STEP 9. 분배 사유 태그 부착 → 팀별 파일 생성                  │
│  STEP 10. HR 담당자 검수 → 확정                                │
└────────────────────────────────────────────────────────────┘
```

STEP 1–2는 **명시지**, STEP 3–8은 **암묵지 → 명시화 대상**, STEP 9–10은 **거버넌스**.

---

## 2. STEP 1. 서류합격자 필터 (명시지)

- **규칙**: `1차서류 결과 == "결과P"` 인 지원자만 남긴다.
- **강도**: **하드 룰**(예외 없음).
- **근거**: 취합파일 전 지원자가 결과P로만 구성되어 있음을 데이터에서 확인.

```python
df = master[master["1차서류 결과"] == "결과P"]
```

---

## 3. STEP 2. R&D 직군 필터 (명시지)

- **규칙**: `R&D/N-R&D == "구분R"` 인 지원자만 이번 회차 팀 배포 대상.
- **강도**: **하드 룰**.
- **근거**: 5개 팀 파일 88행 전원이 `구분R`. N-R&D 지원자는 별도 배포 트랙으로 관리(본 문서 범위 외).

```python
df = df[df["R&D/N-R&D"] == "구분R"]
```

---

## 4. STEP 3. 조직 필터 (부분 암묵지 → 명시화)

- **원칙**: 제1기술원을 기본 배포 조직으로 하되, 제2사업부 지원자는 팀별로 소수 포함한다.
- **강도**: **소프트 룰**(허용 편차 있음).
- **명시화 파라미터**

| 팀 | 제1기술원 목표 | 제2사업부 허용 |
|---|---|---|
| AI솔루션팀 | 100% | 0명 |
| 로봇응용기술팀 | 90%+ | 최대 1명 |
| 미래혁신팀 | 90%+ | 최대 1명 |
| 배터리기술팀 | 85%+ | 최대 2명 |
| 전극기술팀 | 90%+ | 최대 1명 |

- **근거**: 실제 배포 비율 (제1기술원 16/18/16/14/19 vs 제2사업부 0/1/1/2/1).
- **AI 처리 방식**: 팀 프로필의 `org_ratio_target` 필드로 관리, 배치 시 편차 5%p 이내 유지.

---

## 5. STEP 4. 팀별 주력 직무 매칭 (핵심 암묵지 → 명시화)

- **원칙**: 각 팀은 “주력 직무” 1–2개를 갖는다. 후보자의 `1지망_직무` 값이 팀 주력과 맞을수록 우선 배정한다.
- **강도**: **가중 룰**(스코어링).
- **명시화 파라미터 (팀별 주력 직무)**

| 팀 | 주력 직무(1순위) | 보조 직무(2순위) | 목표 비율(주력+보조) |
|---|---|---|---|
| **AI솔루션팀** | 직무다 (D03) | 직무나·직무라 | 80% 이상 |
| **로봇응용기술팀** | 직무나 (D02) | 직무가 | 65% 이상 |
| **미래혁신팀** | (없음, 균등) | 전 직무 | 편차 ±10%p 이내 |
| **배터리기술팀** | 직무가 (D01) | 직무라 (D04) | 55% 이상 |
| **전극기술팀** | 직무나 (D02) | 직무가 | 65% 이상 |

- **근거**: 팀별 실제 직무 분포(예: AI솔루션 직무다 44%, 로봇 직무나 42%, 전극 직무나 40%).
- **AI 처리 방식**
  1. 팀 프로필의 `primary_job`, `secondary_job`, `min_primary_ratio` 참고.
  2. 후보자 스코어링: `primary` 매칭 = +3점, `secondary` = +1점, 그 외 = 0점.
  3. 팀 정원 한도까지 스코어 상위 순으로 배정하되 STEP 5–7 결과를 합산.

---

## 6. STEP 5. 팀별 전공 매칭 (핵심 암묵지 → 명시화)

- **원칙**: 같은 직무라도 전공에 따라 팀 적합도가 다르다. 팀 성격에 부합하는 전공을 우선한다.
- **강도**: **가중 룰**.
- **명시화 파라미터 (팀별 선호 전공군)**

| 팀 | 선호 전공군 | 대표 학과 예시 |
|---|---|---|
| **AI솔루션팀** | 재료 · 지능 · 전산 | 벼리재료학과, 미르지능학과, 빛솔전산학부 |
| **로봇응용기술팀** | 전산 · 정보 · 제어 | 빛솔전산학부, 자람정보학과, 가온제1공학과 |
| **미래혁신팀** | 지능 · 생산 · 산업 | 미르지능학과, 여울생산학과, 가온제1공학과 |
| **배터리기술팀** | 화학 · 소재 · 고분자 | 윤슬고분자학과, 나래제1공학부, 여울생산학과 |
| **전극기술팀** | 설계 · 정밀 · 나노 | 해오름설계학과, 온누리연산학부, 한별나노학과 |

- **근거**: 팀별 최종학력_주전공 상위 3개 학과 데이터 분석.
- **AI 처리 방식**
  1. 팀 프로필의 `preferred_majors` 리스트 유지.
  2. 후보자의 `최종학력_주전공` + `학사1_주전공`이 리스트에 포함되면 +2점.
  3. 회차마다 신규 학과가 등장하면 후보 학과로 태그 후 HR 리뷰.

---

## 7. STEP 6. 학사/대학원 비율 조절 (암묵지 → 명시화)

- **원칙**: 팀마다 “대학원 인원의 적정 비율”을 다르게 유지한다.
- **강도**: **소프트 룰** (편차 ±5%p 허용).
- **명시화 파라미터 (`최종학력_학교유형` 기준: 과정1 = 학사, 과정2/3 = 대학원)**

| 팀 | 대학원 목표 비율 | 실측치 |
|---|---|---|
| AI솔루션팀 | 30% | 31% |
| 로봇응용기술팀 | 20% | 21% |
| 미래혁신팀 | 25% | 24% |
| 배터리기술팀 | 20% | 19% |
| 전극기술팀 | 35% | 35% |

- **근거**: 팀별 학사/대학원 실측 비율.
- **AI 처리 방식**: 배정 완료 후 팀별 대학원 비율을 산출하여 목표치 ±5%p 초과 시 자동 재조정(교체 후보 제시).

---

## 8. STEP 7. 특수 태그 우선 배정 (암묵지 → 명시화)

- **원칙**: 특정 태그가 있는 지원자는 지정 팀에 우선 배정한다.
- **강도**: **하드 룰** (배정 실패 시 알림).
- **대상 태그**

| 태그 컬럼 | 값 | 기본 배정 팀 | 근거 |
|---|---|---|---|
| `타겟랩여부` | Y | 로봇응용기술팀 (실측 유일 사례) | 팀 파일 관찰 |
| `지도교수` | (값 존재) | 로봇응용기술팀 | 팀 파일 관찰 |
| `LG Aimers` | Y | HR 리뷰 필요 (미매핑) | 관찰 부족 |
| `러브지니` | Y | HR 리뷰 필요 (미매핑) | 관찰 부족 |
| `보훈청 추천` | Y | HR 리뷰 필요 | 관찰 부족 |

- **AI 처리 방식**
  1. 특수 태그 지원자는 STEP 4–6보다 먼저 배정.
  2. 배정 실패 시 `manual_review_required = true`로 표시하고 HR에 알림.

---

## 9. STEP 8. 복수 검토 · 중복 배포 관리 (암묵지 → 명시화)

- **원칙**: 두 팀 이상에서 검토가 필요하다고 판단되는 지원자는 **의도적**으로 복수 팀에 배포한다. 이때 반드시 사유를 기록한다.
- **강도**: **거버넌스 룰** (기록 필수).
- **명시화 항목**

| 필드 | 설명 |
|---|---|
| `duplicate_intent` | true / false |
| `duplicate_teams` | 예: ["AI솔루션팀", "로봇응용기술팀"] |
| `duplicate_reason` | 예: "전공(재료) + 직무(D03) 양쪽 팀 관심 프로필" |
| `primary_team` | 최종 주관 팀 1개 지정 (일정 배정용) |

- **근거**: 실측 중복 사례 5건(카기쁨, 나시아, 슬다래, 하은결, 한나래) 중 사유가 파일에 남지 않음.
- **AI 처리 방식**
  1. 중복 배포는 최대 2팀까지만 허용.
  2. `primary_team` 미지정 시 배포 확정 불가.
  3. 중복 배포 시 면접 일정 배정 단계에서는 `primary_team` 기준으로만 배정.

---

## 10. STEP 9. 분배 사유 태그 부착 & 파일 생성

- **원칙**: 팀별 파일 생성 시 각 행에 “왜 이 팀에 왔는가”를 최소 1개 이상 태그로 남긴다.
- **강도**: **하드 룰**.
- **표준 태그 세트**

| 태그 | 조건 |
|---|---|
| `PRIMARY_JOB` | 팀 주력 직무 매칭 |
| `SECONDARY_JOB` | 팀 보조 직무 매칭 |
| `PREFERRED_MAJOR` | 팀 선호 전공군 매칭 |
| `ORG_MAIN` | 제1기술원 (기본 조직) |
| `ORG_ALT_QUOTA` | 제2사업부 쿼터 배정 |
| `TARGET_LAB` | 타겟랩 지정 배정 |
| `ADVISOR_ROUTE` | 지도교수 관계 배정 |
| `GRAD_BALANCE` | 대학원 비율 조정용 배정 |
| `DUPLICATE_REVIEW` | 복수 검토 대상 |
| `HR_MANUAL` | 위 규칙 외 담당자 재량 |

- **파일 스키마 확장**: 팀 배포본에 아래 컬럼 추가.
  - `배포회차`
  - `배포일시`
  - `배포자`
  - `배포사유_태그` (쉼표 구분, 여러 개 가능)
  - `주관팀_여부` (Y/N)
  - `배포_스코어` (STEP 4–7 합산 점수)

---

## 11. STEP 10. HR 담당자 검수 & 확정

- **원칙**: AI가 생성한 배포안은 **자동 확정하지 않는다.** HR 담당자가 검수 후 확정한다.
- **검수 화면 필수 요소**
  1. 팀별 배포 인원 및 목표 대비 편차
  2. 규칙별 준수율 (조직 비율, 주력 직무 비율, 대학원 비율)
  3. 중복 배포 목록과 사유
  4. `HR_MANUAL` 태그가 붙은 재량 배정 로그
  5. 미배포자 목록과 사유 (예: 태그 미매핑, 정원 초과)

- **확정 후 산출물**
  - `희망지원자_{팀명}.xlsx` × N개 (기존 형식 유지)
  - `배포_감사로그.csv` (모든 배포 결정과 태그의 이력)
  - `배포_요약리포트.pdf` (규칙별 준수율, 편차, 예외 사항 요약)

## 13. 스코어링 알고리즘 의사코드

```python
def score_candidate(candidate, team_profile):
    score = 0
    reasons = []

    # 주력/보조 직무
    if candidate.job in team_profile.primary_job:
        score += 3; reasons.append("PRIMARY_JOB")
    elif candidate.job in team_profile.secondary_job:
        score += 1; reasons.append("SECONDARY_JOB")

    # 선호 전공
    majors = {candidate.major_final, candidate.major_bachelor}
    if majors & set(team_profile.preferred_majors):
        score += 2; reasons.append("PREFERRED_MAJOR")

    # 조직 매칭
    if candidate.org == "제1기술원":
        reasons.append("ORG_MAIN")
    elif candidate.org == "제2사업부":
        reasons.append("ORG_ALT_QUOTA")

    # 특수 태그
    if candidate.target_lab == "Y" and "타겟랩" in team_profile.special_tags:
        score += 5; reasons.append("TARGET_LAB")
    if candidate.advisor and "지도교수" in team_profile.special_tags:
        score += 3; reasons.append("ADVISOR_ROUTE")

    return score, reasons


def distribute(master_df, team_profiles):
    # STEP 1–2
    pool = master_df[
        (master_df["1차서류 결과"] == "결과P") &
        (master_df["R&D/N-R&D"] == "구분R")
    ]

    assignments = {t.team_name: [] for t in team_profiles}
    for _, cand in pool.iterrows():
        scored = [(t, *score_candidate(cand, t)) for t in team_profiles]
        scored.sort(key=lambda x: x[1], reverse=True)
        top = scored[0]
        assignments[top[0].team_name].append((cand, top[2]))

        # 복수 검토 후보
        if len(scored) > 1 and scored[1][1] >= top[1] * 0.8:
            assignments[scored[1][0].team_name].append(
                (cand, scored[1][2] + ["DUPLICATE_REVIEW"])
            )

    # STEP 6: 대학원 비율 조정 (사후 밸런싱)
    for team in team_profiles:
        rebalance_grad_ratio(assignments[team.team_name], team.grad_ratio_target)

    return assignments
```

- **팀 프로필 업데이트 주기**: 분기 1회 또는 담당자 재량 배정 임계치 초과 시 즉시.
